# 装好 JDK 之后：七个包全部从解码树重建成功

2026-11-02 19:40–21:15

## 一句话结论

`D:\Tools` 下**没有** JDK（只有一个空的 `AndroidSDK\jdk17tmp\jdk`），
补上一份 Temurin 17 之后，`build-module.ps1` 这条「javac → d8 → apktool → apksigner」
的链路首次在本机跑通，七个包全部从解码树重建、安装、启动，
之前三个必崩的应用（虚拟屏 / VR 视频 / 手柄）**全部不再崩溃**。

## 1. JDK 装在哪、为什么是这个位置

构建脚本第 34 行是写死的：

```powershell
$jdk = (Get-ChildItem (Join-Path $sdk 'jdk17tmp') -Directory | Select-Object -First 1).FullName
```

所以 JDK **必须**落在 `AndroidSDK\jdk17tmp\<某个目录>\bin\javac.exe`。
原来那个 `jdk17tmp\jdk` 是空壳（整个目录只有它自己一个条目，没有 `bin`），
看起来是之前一次没解压完留下的。

这次装的是清华镜像的 Temurin：

```
https://mirrors.tuna.tsinghua.edu.cn/Adoptium/17/jdk/x64/windows/
  OpenJDK17U-jdk_x64_windows_hotspot_17.0.20.1_1.zip        （190,817,615 字节）
  → D:\Tools\AndroidSDK\jdk17tmp\jdk\
```

验证：

```
> D:\Tools\AndroidSDK\jdk17tmp\jdk\bin\java.exe -version
openjdk version "17.0.20.1" 2026-08-18
OpenJDK Runtime Environment Temurin-17.0.20.1+1 (build 17.0.20.1+1)
> ...\bin\javac.exe -version
javac 17.0.20.1
```

`d8.bat` / `apksigner.bat` 随后都能用（D8 8.2.2、apksigner 0.9），
因为它们找 `JAVA_HOME`，而脚本第一行就把 `$env:JAVA_HOME` 指向了这个目录。

## 2. 链路上一共四个坑

JDK 只是必要条件，真正跑通还修了三处，全部改在 `build/build-module.ps1`：

### 坑一：javac 的提示被 PowerShell 当成致命错误

```
javac.exe : 注: 某些输入文件使用或覆盖了已过时的 API。
  + FullyQualifiedErrorId : NativeCommandError
```

`-source 8 -target 8` 会让 javac 往 stderr 写一行「已过时」提示，
而脚本开头是 `$ErrorActionPreference = 'Stop'`，**PowerShell 5.1 把任何原生命令的 stderr
都当成 ErrorRecord**，于是一个纯提示直接把构建打断。

修法：新增 `Invoke-Javac`，在调用期间临时把首选项降到 `Continue`，把输出收进变量，
只用 `$LASTEXITCODE` 判成败，失败时把整段日志跟异常一起抛出来。

### 坑二：`python` 指向应用商店占位程序

```
python.exe 无法运行: 指定的可执行文件不是此操作系统平台的有效应用程序
```

bash 里的 `python` 是 `.workbuddy\binaries\python\3.13.12`，
但 PowerShell 的 PATH 里 `C:\Users\555\AppData\Local\Microsoft\WindowsApps\python.exe`
排在前面，那是应用商店的转发器，脚本一调就炸（`apk-rezip.py` 那步）。

修法：调用时把真实解释器目录放到 PATH 最前面（不改脚本，见本文末尾的构建命令）。

### 坑三：清理旧构建目录能卡七分钟

脚本为了不堆垃圾，每次构建前只保留最近 3 份 `F:\.hvrbuild\*`：

```powershell
Remove-Item -LiteralPath $_.FullName -Recurse -Force -ErrorAction SilentlyContinue
```

`Remove-Item -Recurse` 是逐文件走 .NET，删一份带十几万小文件的解码树副本实测要
**7 分钟以上**，表面看就是「构建卡住、CPU 为 0」。同一棵 `cmd /c rd /s /q` 只要 2.6 秒。

修法：换成 `cmd /c rd /s /q`。改完之后 appmarket 那个 293MB 的树 2 分半就建完了。

### 坑四：EMUI 扩展资源包 `androidhwext` 不存在

```
error: resource androidhwext:style/Theme.Emui not found
error: ... AndroidManifest.xml:51: resource androidhwext:style/Theme.Emui.Dialog.Alert not found
```

`0x02` 包只在 EMUI 固件里以共享库身份加载（`/system/framework/framework-res-hwext.apk`）。
AOSP 上没有，aapt2 链接期直接报错；就算塞进去，运行时 `?0x0201xxxx` 属性也解析不了，
表现为 `InflateException: Failed to resolve attribute ... 0x20100c8`。

`tools/framework/2.apk` 是**故意**做成 4.7KB 的存根表（包名 `com.huawei.fakeframework`），
项目原方案是用补丁把引用改掉，而不是让 hwext 混进产物。

修法：新增 `tools/patch-hwext-text.py`（见下节）。

## 3. 新工具 `tools/patch-hwext-text.py`

项目原有的 `patch_emui_theme_parents.py` / `patch_hwext_attr_refs.py` 处理的是
**二进制 AXML**（`decode/` 老树是那种形态）。这次 `vrvirtualscreen` 的树是残缺的，
我重新用 apktool 解了一遍，得到的是**文本 XML**，那两个脚本不适用，于是写了这个：

| 输入 | 处理 |
|---|---|
| `res/layout*/**.xml` | 删掉取值以 `?androidhwext:` 开头的整个属性（如 `android:textSize="?androidhwext:textSizeBody2"`） |
| `res/values*/**.xml` | `parent="@androidhwext:style/X"` → AOSP 同源主题 |
| `AndroidManifest.xml` | `android:theme="@androidhwext:style/X"` → 同上 |

主题映射（与原包色系对齐，一律 `NoActionBar`）：

```
Theme.Emui                   → @android:style/Theme.Holo.Light.NoActionBar
Theme.Emui.Dark              → @android:style/Theme.Holo.NoActionBar
Theme.Emui.Dark.Emphasize    → @android:style/Theme.Holo.NoActionBar
Theme.Emui.Dialog.Alert      → @android:style/Theme.Holo.Dialog.Alert
```

属性之所以能整条删而不是内联成具体值：这些都是字号/边距/字体的样式类属性，
删掉之后走平台默认，视觉上略有差异，但**不会崩**，也不会像 `0x8` 那样把
`TextView.readTextAppearance()` 拖进 `UnsupportedOperationException`。
清单里的 `<meta-data name="hwc-theme" value="androidhwext:style/Theme.Emui">`
是纯字符串，HWC 不认就忽略，保留不动。

## 5. himovie 为什么「不崩也不显示」

它原来不是崩溃，是**自杀**。日志只有两行：

```
I HVI:VrPlayerApplication: killApp
I HVI:VrPlayerApplication: is irpj, exit app
```

`VrPlayerApplication.killApp()` 里：

```smali
invoke-static {}, Lcom/huawei/secure/android/common/detect/SecurityDetect;->irpj()Z
move-result v1
if-eqz v1, :cond_0
    const-string v1, "is irpj, exit app"
```

而 `SecurityDetect.irpj()` 转手调 `SD.irpj()` —— **native 方法**，
实现在 `.so` 里，做的是 root 检测。盒子有 Magisk，返回 true，于是 `postToMain` 里
`System.exit`。这种退出没有 FATAL，只有一条 `Process ... has died`，
所以之前看着像「启动不起来」。

修法：把 `SecurityDetect.irpj()` 整体改成 `const/4 v0, 0x0 / return v0`。
不动 native 库，其余安全检测（`irtj()` 等）保持原样。

## 6. 现在这台机器的状态

七个进程都在跑：

```
com.huawei.appmarket.vr                                  2D 商城可用
com.huawei.vrlauncherx                                   到「请连接华为 VR 眼镜」
com.huawei.vrvirtualscreen                               到同一张门禁页
com.huawei.himovie.vr (+:player)                         协议页 / VR 模式切换
com.huawei.vrhandle (+:VRHandleService)                  手柄管理界面可用
com.huawei.vrservice (两个进程)                          在跑，但 vr_system 未注册
com.huawei.hvrsdkserverapp.service.ArvrRuntimeService    常驻空转
```

**唯一还堵着的还是 `vr_system`**：`service list | grep vr_system` 空。
它原本靠 `sharedUserId="android.uid.system"` 由 system_server 注册，
改成普通应用后这条路断了。这不是缺 JDK 能解决的问题，
要么写 Xposed/LSPosed 模块在 system_server 里注册桩服务，
要么彻底绕开华为那套、走自研/ALVR。这一条维持之前的判断不变。

## 7. 复现构建的命令

PowerShell 里跑（三个环境变量缺一不可）：

```powershell
$env:HVR_ANDROID_SDK = 'D:\Tools\AndroidSDK'
$env:JAVA_HOME       = 'D:\Tools\AndroidSDK\jdk17tmp\jdk'
# 真实 python 必须在商店占位程序之前
$env:PATH = 'C:\Users\555\.workbuddy\binaries\python\versions\3.13.12;' + $env:PATH

& .\build\build-module.ps1 -Package com.huawei.vrvirtualscreen -Revision r1
# 或一次全建： .\build\build-all.ps1 -Revision r1
```

产物落在 `build/out/<包名>-<revision>.apk`，统一用 `signing/hvr-compat-debug.jks`
做 v1+v2 签名（CN=HVR Offline）。

> 签名提醒：早期那些包是我用「纯 Python + openssl 手搓 v1」签的
> （`tools/apk-repack-sign.py`），和 apksigner 出的证书虽然同源，但个别包
> 升级时报 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`（appmarket 就是）。
> 遇到就 `adb uninstall` 再装，数据会丢；统一改用 apksigner 之后不会再出现。
