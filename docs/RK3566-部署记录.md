> 2026-11-02　目标机：`rk356x_box / H96_Max_RK3566`
> 结果：**七个包全部安装，主应用可启动到 VR 主界面，无崩溃。**

## 二、三处硬卡点

### 卡点 1：`sharedUserId="android.uid.system"`

`hvrsdkserverapp` / `vrlauncherx` / `vrservice` / `vrvirtualscreen` 四个包的 manifest 都声明了
`android:sharedUserId="android.uid.system"`。安装直接报：

```
INSTALL_FAILED_SHARED_USER_INCOMPATIBLE: Reconcile failed:
Package com.huawei.vrservice has no signatures that match those in shared user android.uid.system
```

原因：这四个包在 EMUI 上是**预装的平台签名应用**，与 `android.uid.system` 共享 UID。
RK3566 上的系统 UID 是 Rockchip 平台签名，华为签名对不上，这个共享 UID 永远不可能建立。

处理：去掉这个属性（与 `patches/patch_vrservice_manifest.py` 的口径一致 ——
「保留原包名、原组件、原流程，改为普通应用 + 同签名兼容层」），
失去的 system UID 权限用 `appops` / `pm grant` 显式补（见第五节）。

### 卡点 2：本机没有可用的 JDK

`build/build-module.ps1` 与 `apktool` / `apksigner` 全都依赖 Java。但本机：

- `D:\Tools\AndroidSDK\jdk17tmp\jdk\bin\` 里**只有 `server`**，没有 `java.exe` / `javac.exe`
  （JDK 被裁剪过，`build-module.ps1` 一跑就报 `javac.exe 不是可识别的命令`）
- `where java` 无结果，`C:\Program Files` / `D:\Tools` 全盘也搜不到

于是 `build/out` 里只有 `com.huawei.vrlauncherx-v11.apk` 一个华为包，其余六个没有构建产物。

### 卡点 3：`targetSdkVersion` 决定能不能用 v1 签名

没有 Java 就用不了 `apksigner`。替代方案是自己做 v1（JAR）签名，但 Android 11 的规则是：

- `targetSdkVersion < 30` → 只要求 v1，可以自己签
- `targetSdkVersion >= 30` → **强制 v2**（APK Signing Block），实现成本高得多

七个包的 targetSdk：`appmarket 29` / `himovie 29` / `vrlauncherx 29` / `vrvirtualscreen 29` /
`hvrsdkserverapp 26` / `vrservice 28` / **`vrhandle 31`**。

`vrhandle` 撞上这条规则，报：

```
INSTALL_PARSE_FAILED_NO_CERTIFICATES:
Scanning Failed.: No signature found in package of version 2 or newer
```

处理：把它的 `targetSdkVersion` 从 31 降到 **29**，与其余六包一致。
对手柄这类外设管理应用，targetSdk 29 在 Android 11 上只意味着更宽松的兼容模式
（分区存储、后台启动、包可见性），不影响功能。

## 三、兜底方案：`tools/apk-repack-sign.py`

在「没有 JDK」的前提下，用 **Python + openssl** 完成「改 manifest → 重新打包 → v1 重签」：

```
密钥库 signing/hvr-compat-debug.jks 实际是 PKCS#12（文件头 30 82 0a 4a）
   → openssl pkcs12 -passin pass:android -nodes  导出 key.pem / cert.pem
   → 同一对密钥，七个包才能互相授予 signature 级权限
```

脚本做的事：

1. 用 `patches/axml_edit.py` 直接改二进制 `AndroidManifest.xml`
   （删 `sharedUserId`、改 `targetSdkVersion`），不经过 apktool
2. 丢掉原包 `META-INF/*.SF|*.RSA|*.DSA|*.EC|MANIFEST.MF`
3. 重算 `MANIFEST.MF`（逐条目 SHA-256）与 `CERT.SF`（逐段 + 整份摘要），
   按 JAR 规范折行（每行 ≤ 72 字节）
4. `openssl smime -sign -binary -noattr -outform DER` 生成 detached PKCS#7 作为 `CERT.RSA`
5. 重写 zip，并按 zipalign 规则对齐：`.so` **4096** 字节、`resources.arsc` 与其余未压缩条目 **4** 字节
   （用 `0xD935` padding extra field）

### 踩过的三个坑（都已在脚本里修掉）

| 现象 | 根因 | 修法 |
|---|---|---|
| 装包报 `has no certificates at entry assets/...hwcardview...9.png` | 解析 `MANIFEST.MF` 段落名时只取了折行后的第一行，6 个超长路径被截断，`CERT.SF` 里的 `Name` 与真实条目对不上 | `split_sections()` 把续行拼回去 |
| 装包报 `Failed to extract native libraries, res=-2` | `extractNativeLibs=false` 时 `.so` 必须按页对齐，原来只做了 4 字节 | `alignment_for()`：`.so` 用 4096 |
| 修复上面两条后 `vrhandle` 仍报 `No signature found in package of version 2 or newer` | targetSdk 31 强制 v2 | 加 `--target-sdk 29` |

## 五、运行验证

启动 `com.huawei.appmarket.vr/com.huawei.hwmarket.vr.MainActivity`：

```
Status: ok   LaunchState: COLD   TotalTime: 730
Activity: com.huawei.appmarket.vr/...startevents.protocol.activity.ProtocolActivity
```

依次走完：**隐私声明页 → 5 页引导（阅读提示 / 眼镜度数调节…）→ VR 主界面**
（「欢迎使用华为 VR / 开启 VR 之旅」）。全程无 `FATAL EXCEPTION`、无 ANR，进程稳定（RSS 约 300 MB）。

界面资源、主题、布局、图片全部正常 —— 说明 ARSC 与资源解析没问题
（`resources.arsc` 的对齐处理是对的，否则会直接解析失败）。

### 日志里唯一的一类告警

```
E DeviceTssKit/DeviceTssKitImpl: ClassNotFoundException: com.huawei.android.os.BuildEx
W HwWidgetSafeInsets: getDisplaySafeInsets ClassNotFoundException
E HwReflectUtil: ClassNotFoundException in reflect call getBoolean
W AppGalleryVR.HwViewPagerStepper: ClassNotFoundException
```

全是**华为 EMUI 框架类缺失**，且都被调用方 catch 住了（应用继续跑）。
这正是 `shared/java` 那 40 个平台类要补的东西；在 RK3566 上要注入生效需要
LSPosed 或 bundled dex，本轮未做。

### 授权补齐（`tools/grant-vr-perms.sh`）

已执行：`appops WRITE_SETTINGS / SYSTEM_ALERT_WINDOW / GET_USAGE_STATS`、
`pm grant WRITE_SECURE_SETTINGS / READ_PHONE_STATE / ACCESS_FINE_LOCATION / ACCESS_COARSE_LOCATION`、
`deviceidle whitelist`、`setprop log.tag.HvrFramework|VrHelmetExt ASSERT`、
`wm set-ignore-orientation-request false`。

**有一处遗留**：`appops set` 对 **未在 manifest 声明对应权限**的包不生效
（读回仍是 `default`）。实测：

| 包 | SYSTEM_ALERT_WINDOW 声明 | appops 结果 |
|---|---|---|
| `vrlauncherx` | 有（项目补过） | allow ✔ |
| `vrvirtualscreen` | 有 | allow ✔ |
| `vrhandle` | **无** | default ✘ |
| `vrservice` | **无** | default ✘ |
| `hvrsdkserverapp` | **无** | default ✘ |

要让 `appops set` 生效，得先在这几个包的 manifest 里补
`<uses-permission android:name="android.permission.SYSTEM_ALERT_WINDOW"/>`
（`patches/patch_platform_permissions.py` 里有完整的逐包权限表，照抄即可），
再用 `apk-repack-sign.py --add-permission` 重签重装。
缺这条的后果是：后台启动 Activity / 前台服务会被 Android 11 拦掉，
表现为「桌面进不去 VR 空间」「手柄屡次停止运行」。

## 六、复现步骤

```bash
# 0. 前提：设备已 root（Magisk），且支持 armeabi-v7a
adb connect 192.168.43.133:5555

# 1. 导出签名密钥（只需一次）
openssl pkcs12 -in signing/hvr-compat-debug.jks -nodes -passin pass:android \
    -nocerts -out .tmp-sign/key.pem
openssl pkcs12 -in signing/hvr-compat-debug.jks -nokeys -passin pass:android \
    -clcerts -out .tmp-sign/cert.pem

# 2. 对需要处理的包改 manifest + 重签
#    有 sharedUserId 的四个
python tools/apk-repack-sign.py 原包/com.huawei.vrservice.apk          .tmp/a6.apk
python tools/apk-repack-sign.py 原包/com.huawei.hvrsdkserverapp.apk    .tmp/a3.apk
python tools/apk-repack-sign.py 原包/com.huawei.vrvirtualscreen.apk    .tmp/a7.apk
#    没有 sharedUserId、但 targetSdk 过高的
python tools/apk-repack-sign.py 原包/com.huawei.vrhandle.apk .tmp/a4.apk --target-sdk 29
#    其余两个只统一签名
python tools/apk-repack-sign.py 原包/com.huawei.appmarket.vr.apk .tmp/a1.apk
python tools/apk-repack-sign.py 原包/com.huawei.himovie.vr.apk   .tmp/a2.apk

# 3. 安装（launcherx 用项目已有补丁产物）
adb install -r -d build/out/com.huawei.vrlauncherx-v11.apk
for f in a1 a2 a3 a4 a6 a7; do adb install -r -d .tmp/$f.apk; done

# 4. 补授权
sh tools/grant-vr-perms.sh 192.168.43.133:5555

# 5. 启动
adb shell am start -W -n com.huawei.appmarket.vr/com.huawei.hwmarket.vr.MainActivity
```

> 注意：`apk-repack-sign.py` 处理中文路径没问题（纯 Python），但 `aapt` / `apktool` / `aapt2`
> 这些原生程序打不开中文路径，需要先把 APK 复制到 ASCII 目录再调用。

## 七、还差什么

1. **补 `SYSTEM_ALERT_WINDOW` 等声明**，让 `appops` 真正生效（见第五节遗留）
2. **`vr_system` 门禁**：主界面「开启 VR 之旅」要眼镜在位且 `vr_system` binder 存在，
   `com.huawei.vrservice` 是注册方 —— 但它是普通应用安装的，注册不到 system_server
3. **显示通路**：盒子只有 HDMI，`hvrglass` 模块已经在喂 3200×1600@70 EDID，
   接上眼镜后要验证 HWC 是否真的输出该模式
4. **平台类注入**：`shared/java` 那 40 个类（`BuildEx`、`HwWidgetSafeInsets` 等）
   需要 LSPosed 或 bundled dex 才能在非华为系统上生效
