# ALVR 保帧配置清单（不降帧提流畅度）

> 目标：**帧数不降**（每眼 30fps / 双眼交替 60fps 是 SDK 固有设计，见
> `VR桌面-2026-11-26-稳定性与手柄修复.md` §5/§7），在保帧前提下降低每帧负载，
> 让帧更稳、延迟更低。本清单只改 **PC 端 ALVR Dashboard 设置**，不改仓库代码、
> 不重编 dex、不动手机系统属性。

## 为什么这样调

卡顿根因是 `swapBuffer 5~13ms`（正常 <2ms）——3200×1600 双目合成的 GPU 带宽开销。
在保帧约束下，能动的只有「每帧要搬多少像素、编多少码」：

- **物理面板 3200×1600（每眼 1600×1600）不能动**：这是 SBS 结构，动了画面就错。
- **渲染/编码分辨率可以降**：小分辨率渲染后由硬件上采样到面板，帧数不变、画面稍软，
  但 GPU 合成与编码负载显著下降。这正是 `ALVR_HUAWEI_VR_GLASS.md` §3.3/§115 记录的
  官方「性能不足时」做法。

## 一、Dashboard 参数（改完点 Save，重连生效）

| 设置项 | 当前值（推荐初始） | 保帧目标值 | 作用 / 代价 |
|---|---|---|---|
| 编解码单眼分辨率 | 1.0×（1536×1536） | **896×896/眼** | 编码像素量降到约 34%，帧更稳；画面稍软 |
| 模拟头显单眼分辨率 | 1.0×（1536×1536） | **保持 1.0×，不要动** | 维持正确 FOV 与几何关系，动头显分辨率会变形 |
| 首选刷新率 | 72Hz（实际 70Hz） | **保持 72Hz** | 这是帧数本身，不降 |
| 编解码器 | H.264 | **H.264 + `OMX.qcom.video.decoder.avc` 硬解** | 高通 7T 上 hisi 组件不存在，必须走 qcom（dex 已改，见 `ALVR-QCOM-DECODER.md`） |
| 码率 | 14 Mbps 起步 | **8~10 Mbps** | 带宽压力小、卡顿少；过低会糊，按画质回调 |
| 网络协议 | TCP | **保持 TCP** | 稳；UDP 在弱网下抖动更大 |
| 客户端缓冲 | 1 帧 | **保持 1 帧** | 加大缓冲降抖动但增延迟，VR 里延迟更晕 |
| PC 待发送队列 | 1 帧 | **保持 1 帧** | 同上 |
| 固定注视点编码（FFE） | 关闭 | **保持关闭** | FFE 省算力但周边糊；若仍卡可试开启，接受周边画质损失 |

**关键点**：只动「编解码单眼分辨率」和「码率」两项，**模拟头显分辨率、刷新率、
缓冲都不要动**——前者决定几何/FOV，后两者就是帧数和延迟本身。

## 二、改完怎么验证（缺一不可）

1. **帧数没降**（硬约束）：SteamVR 性能图 / ALVR Dashboard 统计里，`fps` 仍显示
   每眼约 30fps、双眼交替约 60fps。若明显低于此值，回退本次改动——不是我们调的目标。
2. **负载确实降了**：PC 端任务管理器看 ALVR 进程的 GPU/编码器占用下降；手机端
   `adb logcat -s HvrMirrorService` 不再频繁出现 `swapBuffer cost too much time: 5~13ms`
   （这是投屏镜像线；VR 桌面线看 SteamVR 帧时间更稳）。
3. **画面没变形**：戴镜确认 FOV、几何关系不变（因头显分辨率未动）；若画面偏广角/变形，
   检查是不是误改了「模拟头显分辨率」。
4. **硬解生效**：`adb logcat` 过滤 `OMX.qcom` / `MediaCodec`，确认解码器是 qcom 而非
   软件回退；若出现 `OMX.hisi.video.decoder` 说明 dex 未升级，重跑 `launch_alvr.sh`
   （日志应出现 `patched ALVR classes.dex (qcom decoder)`）。

## 三、仍卡时的下一步（按序，不降帧）

1. 编解码分辨率再降到 **768×768/眼**（头显保持 1.0×）；
2. 码率降到 **6 Mbps**；
3. 网络换成 5GHz 独立网段或网线，排除 AP 隔离/频段切换导致的抖动；
4. 关掉 PC 上抢占 GPU 的应用（录屏、浏览器硬件解码）；
5. 以上都不够 → 是 `swapBuffer` 合成拷贝的固有开销，配置层已到极限，
   只剩**前缓冲直出**（`IVrServiceManager.startFrontBufferDisplay`）这条路，
   见 `docs/ALVR-前缓冲直出-可行性评估.md`（属 native/平台层，非配置可解）。

## 四、边界

- 这是 **Dashboard 侧配置**，不同 ALVR 发行版的参数名/位置可能不同；专版
  （Huawei OpenXR Pose Action）以实际界面为准。
- 清单里的分辨率/码率是**起点**，最终值按你的真机流畅度和画质权衡微调；
  唯一不能妥协的是「帧数不降」这条硬约束。
- 沙箱抓不到眼镜那路屏，也读不到 SteamVR 帧数——所有验证项都要在你插镜的真机上完成。
