# 原版 ALVR 眼镜里黑屏 / 连不上服务端 —— 2026-11-27 修复记录

## 结论

眼镜里 ALVR 黑屏不是「没连 PC 服务端」的预期表现，而是**四层故障叠加**，
每一层都会让 native 渲染线程在出图前 panic。现已全部定位并修复。

## 故障链与修复

### 1. 守护把 ALVR 切前台误判为「桌面掉了」（每 ~74s 杀一次 ALVR）
- `vrglass-autostart-new/service.sh` 原来用 `mResumedActivity.*vrlauncherx/.MainActivity`
  判桌面存活。ALVR 一起前台，MainActivity 退到后台 → 守护执行
  `start_vr_desktop.sh` 的 `am force-stop` 整条 VR 链，把 ALVR 一起杀掉。
- 修复：`desktop_running()` 改为 `pidof com.huawei.vrlauncherx`。

### 2. registry provider 的 signature 权限拒绝
- `VrSystemRegistryProvider` 带 `android:permission="com.huawei.vrservice.CLIENT_SERVICE"`
  (signature|privileged)。原版 ALVR 非同签名，读 registry 被拒 →
  `VrMonitor.isVRMode()` 失败。
- 修复：重打包 launcherx（apktool `d -s` 保留 4 个 dex 原样），去掉该权限，
  同证书重签（`build/tmp/lx_noperm_aligned.apk`，md5 `9efa17b6`，证书 `30094ded`）。
  该 provider 本就是我们为通用安卓加的兼容层，不代答状态，只转发真实 binder。

### 3. OpenXR loader 组合错误 → `ERROR_HANDLE_INVALID` panic at `lib.rs:219`
- 原版 APK 只有 965KB `libxr_loader.so`（华为 runtime）。早前把它直接改名成
  `libopenxr_loader.so`，导致 `xr::Entry::load_from()` 后调用
  `initialize_android_loader().unwrap()` 返回 `ERROR_HANDLE_INVALID`。
- 真正需要的是 **74KB Khronos loader 前端**（md5 `f864cac5`）→ 它再 dlopen
  965KB `libxr_loader.so`。产物：`libopenxr_loader.74k.so`（已随模块入库）。
- 另一个更深层原因：平台检测只看 `android.os.Build.MANUFACTURER`。一加是
  `OnePlus` → `Platform::AndroidUnknown` → 走通用分支才调
  `initialize_android_loader()`。源码
  `alvr/system_info/src/lib.rs:162` 明确：厂商名为 HUAWEI/HONOR 才判定
  `Platform::HuaweiVrGlass`。
- 修复：模块 `system.prop` 写 `ro.product.manufacturer=HUAWEI`，Magisk 在
  zygote 前应用，`Build.MANUFACTURER` 初始化即读到 HUAWEI。验证日志：
  `detected platform: HUAWEI VR Glass`、列出 `xrJumpToLauncherHW` 等华为专有扩展。

### 4. 三个华为服务绑定抛 SecurityException → `storage.rs:15` panic
- 走华为分支后，`VrFramework$TemperatureReceiver.register()` 依次调用
  `VrParamsRequester.bindVrService/bindVrLauncherx/bindRuntimeService`，
  三者都 bind 签名权限保护的华为服务，抛 `SecurityException`；异常在 native
  渲染线程冒泡成 `JavaException`，令 `app_dirs2::app_root()` panic。
- 修复：`alvr_hvr.bindfix.dex`（md5 `b1db7e94`）把三个方法开头改成
  `return-void`。温度/参数服务对串流非必需。
  注意：这些方法在 **`hvrframework.dex`** 里，不在 `classes.dex`，第一次
  补丁打错文件白折腾了一轮。`launch_alvr.sh` 现在会幂等部署两个 dex。

### 5. 权限
- zygote 重启后 `READ/WRITE_EXTERNAL_STORAGE`、`RECORD_AUDIO`、
  `ACCESS_MEDIA_LOCATION` 被撤销，Activity 卡在 GrantPermissionsActivity。
  `launch_alvr.sh` 每轮幂等 `pm grant` 回补。

## 验证状态（2026-11-27 18:36）
- ALVR 进程稳定存活，Activity resumed，**无任何 panic / FATAL / SecurityException**。
- 日志进入 `HxrSession::hxrSyncActions` 持续循环（华为 XR session 正常运行）。
- `vr_system_state: true` 持续发布；守护不再循环重启桌面。
- **待用户戴镜确认画面**（机器全绿 ≠ 图层正确，唯一权威判据是戴镜看）。
- PC 端 ALVR 服务端/SteamVR 仍需另行启动，手机端才会真正连上串流。
