# VR 桌面稳定性 + 手柄自动连接修复（2026-11-26，新内核 OnePlus7T/Android11）

> 本文件固化当天定位到的**三个根因**及其可复现补丁。设备侧最终状态见
> `.workbuddy/memory/2026-11-26.md`（逐轮证据）。所有补丁都在 `fix/patches/vrdesktop/`。

## 1. VR 桌面「约 4~38 秒后消失」——native 每帧 JNI 触发 ART SIGABRT

### 现象
启动 VR 桌面后，眼镜屏（display 1）一开始有 3D MainActivity，约半分钟后
`stacks=0`、退回准备页。此前误判为 `Activity top resumed state loss timeout`（那是结果）。

### 根因（native 栈是决定性证据）
```
Thread-18 (Unity 渲染线程)
  libvrunityplugin.so HVR_TimeWarpEvent
  -> libvrsdk.so HvrApiImp::submitFrame -> RenderModule::SubmitFrame -> DrawFence
  -> HvrJniClass::CallStaticBooleanMethod        (native 每帧调 Java 静态方法)
  -> com.huawei.vrframework.VrFramework$VrDisplay.Is6DoFApp (VrFramework.java:1572)
  -> VrInteractiveDeviceManager.getMetaData (line 425)
  -> ART EnsureInitialized -> VerifyClass -> VerifyISFieldAccess -> FindClass
  -> AssertNoPendingException -> Runtime::Abort -> SIGABRT
```
进程死 -> Force finishing MainActivity -> token died -> HUAWEI VR Display 被回收。

### 修复
`fix/patches/vrdesktop/fix_is6dof_art_abort.py`：把 `Is6DoFApp()Z` 开头改成纯
`const/4 v0,0x1; return v0`。原逻辑对 vr_only app 最终也返回 true，语义等价，
但彻底绕开每帧 getMetaData 的类初始化校验。
**注意**：不可跨类 `sput` private static 字段，否则 ART 抛
`ThrowIllegalAccessErrorField`（另一种 SIGABRT）。

产物基线：`hvrframework.dex` 的 vrmode 版 `3120a637`（含 deinit null 兜底 +
isVRMode 兜底）→ 打补丁后 `hvrframework.6doffix2.dex`=`769bd170`（+12B，
dexdump/baksmali 双校验通过）。部署到**两处**：
```
/data/local/tmp/orig/hvrframework.dex                        (启动脚本 restore 源)
/data/data/com.huawei.vrlauncherx/app_SdkLibs/hvrframework.dex (运行时)
chown 10240:10240 + chmod 600；原版备份 .pre-6dof
```
验证：T+80s/T+140s ART abort=0、launcherx 同一 PID 存活、display1 stacks=1、
桌面不再消失。

### 排障要点
- `su -c cat <binary>` 经 adb 文本通道拉 dex 会**损坏二进制**（CRC/尺寸变化）。
  必须 `su -c cp` 到 /sdcard 再 `adb pull`。
- baksmali 宽松、ART verifier 严格：改 dex 后必须 `dexdump -f` 严格校验。
- 手柄 GATT notification 日志会把 logcat 刷爆（实测 14000+ 条），查崩溃要过滤。

## 2. 手柄打开管理界面/点击就崩——缺华为私有类与资源

### 三个独立崩溃点（今天重装 VR 框架把历史补丁覆盖成裸包所致）
1. `CableActivity.r0()` 调 `ActionBarEx.setAppbarBackground` -> NoClassDefFoundError
   （打开 OTA 升级页崩）
2. `layout-v29/commonui_custom_titlebar.xml` 引用 `?androidhwext:maxPaddingStart`
   （attr 0x20100c8，AOSP 无）-> InflateException（点图标进主界面崩）。
   v29 目录共 24 文件/214 处 hwext 属性 + 2 处 `<include @androidhwext:layout/...>`。
3. GATT 回调 `ReporterFactory.<clinit>` 读 `BuildEx$VERSION.EMUI_SDK_INT`
   -> NoClassDefFoundError（接协议后崩）。

### 修复
`fix/patches/vrdesktop/apply_vrhandle_allfix.sh`（一次性打全套）：
- 自动扫描配对：`inject_autoscan.py` + manifest `ACCESS_BACKGROUND_LOCATION`
  （纯后台 BLE 扫描的关键，原包未声明该权限）
- ActionBarEx / BuildEx$VERSION 桩类（`stubs/`，BuildEx$VERSION 用零依赖版：
  `EMUI_SDK_INT=0`，不依赖 vrhandle dex 里没有的 SystemPropertiesEx）
- 布局 hwext 清理：apktool 解码后用 `fix/tools/patch-hwext-text.py`，残留的
  `<include @androidhwext:layout/emui_list_right_only_arrow>` 换成
  `<ImageView src=@drawable/abc_ic_arrow_drop_right_black_24dp>`，再 apktool 全量重编
  （重编后校验 classes.dex 逐字节不变、三项补丁仍在）。
同证书 `30094ded` 重签，`pm install -r` 覆盖。产物基线
`build/tmp/vh_allfix_signed.apk`=`e6969029`。

### 验证
`AutoScanCompat: device found: HUAWEI CF20_45AB -> connect + persist`、
`vrhandle_VrDeviceService: connected to gatt server`、
`sp_device_storage.xml` 落盘 CF20(MAC F7:2D:DD:63:45:AB, connectState=2)。
手柄自动连接确认成功。

## 3. 双眼方向（rflip2 档）
`17t/tools/rotation/make_vrsdk_rot_v4_rflip.py` 的 rflip 档第二分量符号
2026-11-26 订正为 `+ES`（旧 `-ES` 把两眼都改成镜像/翻转，用户反馈

用户戴镜确认"位置对了"。旧 rflip `1c3e7da2` 作废。

## 4. 已知未解（非本次范围）
- **手柄按键/主页键进不去 Unity**：`VrControllerManager: mUsingCtrl == null` 高频刷屏
  + `Unity_HVRController: Right controller is not available in Update`、
  `m_Controller is null in UpdateControllerPos`。即 BLE GATT 虽连上
  （`connected to gatt server`），但 VR SDK 的 `VrControllerManager` 从未把 CF20
  注册为"using controller"，Unity 侧拿不到控制器对象 → 按键/主页键无响应。
  历史（11-01/11-08）已确认：CF20 不在系统输入设备（只有眼镜本体的 GLASS HID），
  按键只走 GATT；`mUsingCtrl==null` 属 3DoF 链未闭合，与 `VRReportPsi: null
  mdeviceID`（眼镜设备未真正注册）同源。蓝牙栈另有
  `bta_gattc_process_indicate, ignore HID ind/notification` 每次连接刷屏。
  要修需深入 VR SDK 控制器注册链，工作量大。
- **渲染卡顿**：`swapBuffer cost too much time: 5~13ms`（正常 <2ms）、
  `chooseFrame wait too long time: 0.016s`，帧时间 ~33ms（约 30fps）。
  3200x1600 双目 GPU 合成吃力；手柄 GATT 通知洪泛也占 CPU。
- vrservice `SecurityException launchDisplayId=N` 自激（已知，不杀主会话）。

## 5. 追加修复：自动配对污染 + 卡顿真相（21:10）
- **根因**：`AutoScanCompat.onDeviceFound` 原本对任何有名字的 BLE 设备都
  `connect + persist`，把附近的小米手表(`82:77:16:C6:E3:B5`)、体脂秤、EDIFIER
  音箱全写入 `sp_device_storage.xml`。vrhandle 心跳对这些非手柄设备无限重连
  （`start to connect ble device with name = Xiaomi Watch` → cancelOpen → 重试），
  logcat 疯狂刷屏、占蓝牙栈与 CPU。
- **修复**：在 `AutoScanCompat.smali` 的 `getName()` 之后加白名单——
  `name.toUpperCase().contains("CF20")` 才入库，其余 `return-void`。
  同步清理设备现有 `sp_device_storage.xml`（备份 `.pre-filter`），只留 CF20。
  重打包 `build/tmp/vh_filter_signed.apk`（md5 `3273eba5`，同证书 `30094ded`
  覆盖安装），四项补丁齐全：CF20 过滤 + AutoScanCompat + ActionBarEx + BuildEx。
- **验证（重启 VR 桌面 65s）**：入库仅 `1 CF20`（其他设备 0）、Xiaomi Watch 刷屏 0、
  ART abort 0、display 1 stacks=1、手柄 FATAL 0。
- **卡顿真相（订正 §4）**：清理后错误设备刷屏归零，但 fps 仍
  `fps0/fps1≈30、fps2≈59.5`、慢帧仍多——**卡顿与设备刷屏无关**，是 SDK
  固有每眼 30fps（双眼交替 60fps），历史基线一直 fps2≈59.6。`swapBuffer 5~13ms`
  是 3200x1600 双目 GPU 合成的固有警告，非新退化。CPU 大核(c7)闲置 825MHz、
  中核(c5)已达 2.4GHz，schedutil 调度；非降频故障。桌面"卡"主要是主观每眼 30fps
  感知 + 手柄按键无响应(§4)叠加，非渲染管线异常。

## 6. 根治「反复启动 / 屡次停止运行」弹窗循环（21:35）
- **现象**：系统反复弹「华为 VR 桌面屡次停止运行」，虚拟屏 displayId 一路递增
  (26→230+)，vrservice 子进程周期性崩溃。清 dropbox 计数只能缓解几十秒后复发。
- **真相**：`VRPrepareActivity` 在 manifest 里声明 `android:process="com.huawei.vrservice"`，
  跑在 vrservice 进程。华为适配流程 `w0/b.t()`→`w0/b.C()`(startPrepareActivity)
  用 launchDisplayId 拉它到 HUAWEI VR Display 虚拟屏；该虚拟屏被 launcherx 反复
  创建/销毁，启动瞬间 id 已失效 → ActivityManager 拒 `launchDisplayId` →
  `SecurityException` → vrservice 崩 → 累积崩溃弹窗 → 重建虚拟屏 → 循环。
  3D MainActivity 在物理 display 1，全程未受影响（戴镜画面正常）。
- **修复**：`fix/patches/vrdesktop/fix_prepare_crash_loop.py` 给 `w0/b.C()` 开头加
  `return-void`，彻底不启动准备页（3D 桌面走独立路径）。重编 classes.dex 替换进
  launcherx APK，重签 `build/tmp/lx_preparefix_signed.apk`（md5 `d3f0e6cd`，
  同证书 30094ded）。私有库 `libvrsdk.so=972a2e06`/`hvrframework.dex=769bd170`
  未变（pm install -r 保留 data）。
- **验证（90s + 180s 两轮）**：startPrepareActivity=0、vrservice FATAL=0、
  AppError 弹窗=0、ART abort=0；display 仅剩 0/1，无递增失效虚拟屏；
  display 1 stacks=1、3D MainActivity 稳定。根治确认。
- 回滚：`build/tmp/lx.apk.pre-preparefix`（原 launcherx APK）。

## 7. 头显移动卡顿真相 + 手柄控制链最终诊断（21:47）
### 头显移动"加载慢"
- IMU 数据实测满速有效：`receive imu data count(1000)/秒, invalid=0`，
  `WallexHid sensorDataStatics invalid count(0)` —— 与 11-14 记录的"59B 只识别 0B"
  完全不同，头追 native 链路是活的（画面随头动）。
- `VrHelmetExt: mVRDeviceExt is null` 是 Java 层观测日志，native 头姿态不依赖它，
  不影响实际头追。
- 卡顿真相：`fps0/fps1≈30`（每眼 30fps，双眼交替 60fps）是 SDK 固有设计；
  `swapBuffer 5~13ms` 是 3200×1600 双目 Adreno 640 GPU 合成开销，物理上限。
  `persist.sys.perf=yes` + perf HAL 已开，CPU_LVL/GPU_LVL=2 是 SDK 内部算的，无 prop 可调。
  → 头动时"慢"= 每眼 30fps 感知延迟，非 bug，无法通过配置提升（除非降分辨率）。
- 已做：`fix_controller_log_flood.py` 把两条高频控制器日志（mUsingCtrl==null ~140/s、
  6Dof false ~60/s）从 Error/Info 降为 Verbose，减少 logcat 开销与"屡次停止"误计数。
  实测日志级别确实变 V，但 fps/swap 无变化 ⇒ 日志非瓶颈；补丁无害保留。

### 手柄控制 VR 桌面 — 多环节断裂，判定为大工程（未强改）
CF20 本轮真连上（connected to gatt server + ACL + 服务发现 + notification 注册），
GATT notification 13634 条在刷，但控制不了桌面。追到底层链：
1. `VrControllerManager.init()` 从未被调用（无 "Controller init enter" 日志）→
   mUsingCtrl / mVRDeviceExt / mAppActivity 全 null；
2. `chooseController()` 读 `UsingCtrl` 配置，而 onVrModeChanged(true) 每次清空且不重选；
3. `ThirdPartyController.getValidIndices()` 依赖 mVRDeviceExt（只在 initVrController 赋值，未调用）；
4. 手柄按键被蓝牙栈当媒体键处理（MediaSessionManager OnMediaKeyEventSessionChanged），
   未进 VR 控制器通道；`bta_gattc ignore HID ind/notification` 历史高频；
5. `VRReportPsi: null mdeviceID` 眼镜设备未注册。
→ 强行在 framework 塞 init 调用风险高（参考 Is6DoFApp 的 IllegalAccessError abort 教训），
  且后面数关未必过。判定为大工程，不盲目改，避免破坏已稳定的桌面。

## 8. 控制器子系统初始化打通（22:00–22:15，重大进展）
- **突破**：`VrFramework.init(activity)` 其实被调用（"VrFramework init" 日志 ×3/进程），
  但原厂依赖组件被裁剪，从不调用 `VrControllerManager.init()` → mUsingCtrl/mVRDeviceExt
  一直 null。（之前"从未调用 VrFramework.init"的判断是清日志后 grep 时机错误。）
- **fix/patches/vrdesktop/fix_controller_init.py** 三处补丁（基于 357eb221）：
  1. VrFramework.init 设置 mAppActivity 后调用 `VrControllerManager.getInstanceObject().init(activity)`（try/catch）；
  2. VrControllerManager.init 强制走 `mThirdPartyCtrl.init(activity)`（原被 isHW6DoF/isNolo 标志跳过，CF20 是 3DoF BLE 走这条）；
  3. chooseController 的 UsingCtrl 为空分支默认选 mThirdPartyCtrl（本环境 onVrModeChanged 每次清空）。
- **产物** `build/tmp/hvr_ctrlinit_v2.dex` md5 `91d493ed`（部署两处）。脚本可从 357eb221 复现（smali 逐字节一致）。
- **验证**：`Thirdparty controller init succeed` + `mUsingCtrl set to ThirdPartyCtrl` 均出现；
  当前进程 "mUsingCtrl == null" 从 ~6960 降到 **0**；ART abort=0、display1 stacks=1 稳定。
- **仍未通**：`Right controller is not available` 仍在（~570/12s）。原因：
  `ThirdPartyController.getValidIndices()` 依赖 `VrInteractiveDeviceManager.getCurrentDeviceList()`
  （华为 AIDL 服务 IHWVRInteractiveDevice 上报的 DeviceInfo），CF20 直连 vrhandle BLE 未进该链，
  设备列表空 → Unity 拿不到控制器数据。下一步需伪造 DeviceInfo 上报或接 vrhandle→AIDL 桥。
- 回滚：`build/tmp/hvr.pre-ctrlinit.dex`（357eb221，含 Is6DoFApp 修复+日志降级，无控制器 init）。
