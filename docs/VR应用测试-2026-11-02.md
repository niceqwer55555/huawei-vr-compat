## 逐个说明

### 1. 应用市场 `com.huawei.appmarket.vr` — 唯一完整可用的

`MainActivity` 直接进到 2D 商城：推荐 banner、搜索框、热门应用、底部四个 tab 全部正常渲染，进程常驻。

```
Status: ok   Activity: com.huawei.hwmarket.vr.MarketActivity
```

### 2. VR 桌面 `com.huawei.vrlauncherx` — 隐私页有坑，VR 空间被门禁挡

**坑一（已解决）**：走 `Vr2dStartUpActivity` → 隐私声明 → 点「同意」直接崩：

```
java.lang.IllegalArgumentException: You cannot keep your settings in the secure settings.
    at android.provider.Settings$System.putIntForUser(Settings.java:3367)
    at q2.e.b(PrivacytHelper.java:4)
    at com.huawei.vrlauncherx.activity.PrivacyStatementActivity.a(PrivacyStatementActivity.java:1)
```

反编译确认它写的是 `Settings.System` 里的自定义键 `PRIVACY_ACCEPTED`。**Android 11 禁止应用往 Settings.System 写非公开键**，EMUI 上被放行，AOSP 上直接抛异常。

绕过（不用改包）：

```sh
adb shell su -c 'settings put system PRIVACY_ACCEPTED 1'
```

`q2/e.a()` 读到 1 就直接跳过隐私页，不再触发写操作。

**坑二（未解决）**：跳过隐私页后进入 `Vr2dStartUpActivity`，弹窗拦住：

> 若要使用该应用，请连接华为 VR 眼镜
> 当前系统版本或机型不支持打开该应用。了解更多信息，请「查看帮助」。

这就是 `isAbleToLaunchInVr` 的门禁，需要：
- 眼镜在位且 `vr_system` binder 可用（`service list | grep vr_system` 现在**为空**）
- `getCurrentDevices().size()==3`（头显 + 左右手柄）

`MainActivity` 可以强行拉起（2D 界面和商城几乎一样），但那是 2D 壳，不是 VR 空间。

### 3. 手柄 `com.huawei.vrhandle` — 服务活着，UI 崩在华为主题属性

```
android.view.InflateException: Binary XML file line #6 in
  com.huawei.vrhandle:layout/commonui_custom_titlebar:
  Failed to resolve attribute at index 7: TypedValue{t=0x2/d=0x20100c8}
    at q0.n.<init>(CustomActionBar.java:73)
    at com.huawei.vrhandle.fragments.BaseFragment.onAttach(BaseFragment.java:19)
```

`0x020100c8` 是**资源包 ID 0x02**（华为 `frameworkhwext`）里的属性。AOSP 上这个包不存在，`TypedArray.getDimensionPixelSize` 拿不到值 → 直接抛 `UnsupportedOperationException`。凡是带华为自定义标题栏的页面都会崩。

好消息：`VRHandleService`（`:VRHandleService` 进程）一直正常跑着，手柄连接逻辑不依赖 UI。

### 4. 虚拟屏 `com.huawei.vrvirtualscreen` — 缺框架类

```
java.lang.NoClassDefFoundError: Failed resolution of: Lcom/huawei/android/os/SystemPropertiesEx;
Caused by: java.lang.ClassNotFoundException: com.huawei.android.os.SystemPropertiesEx
```

`Vr2dStartUpActivity` 起不来。另一个入口 `MainActivity` 被签名级权限挡在系统层：

```
java.lang.SecurityException: Permission Denial: starting ... requires
  com.huawei.vr.permission.VRVIRTUALSCREEN
```

（adbd 的 shell uid 2000 没有该权限，只能由声明了 `uses-permission` 的同签名包拉起。）

### 5. VR 视频 `com.huawei.himovie.vr` — 同一个缺失类，静默退出

```
E HVI:DeviceUtils: java.lang.NoClassDefFoundError: Failed resolution of: Lcom/huawei/android/os/SystemPropertiesEx;
    at cru.a(...) → cpq.a(...) → agz.a(...) → VrPlayerApplication.onCreate(Unknown Source:65)
I ActivityManager: Process com.huawei.himovie.vr (pid 5860) has died: fg  TOP
```

异常被 `DeviceUtils` 自己 catch 掉了，但应用随后自己退出（没走到 `AndroidRuntime` 的 FATAL）。所以 logcat 里只有 `E HVI:DeviceUtils` 没有崩溃堆栈 —— 排查时容易漏。

### 6. VR 服务 `com.huawei.vrservice` — 装了，但注册不了 `vr_system`

包里只有两个组件：

```
com.huawei.vrservice/.UsbReceiver
com.huawei.vrservice/com.huawei.vrinstaller.provider.SharedPreferenceProvider
```

进程会因为 USB 事件起来（`u0_a73 8499`），但 `service list` 里始终没有 `vr_system`。原因是它原本靠 `sharedUserId="android.uid.system"` 以 system uid 向 `SystemServiceManager` 注册服务；被我们改成普通应用后这条路断了。

`vr_system` 是整条链路的总闸：桌面进 VR 空间、虚拟屏投屏、SDK 运行时握手，全部依赖它。

### 7. SDK 运行时 `com.huawei.hvrsdkserverapp` — 在跑但空转

```
u0_a76  7142  ...  com.huawei.hvrsdkserverapp.service.ArvrRuntimeService
```

无 Activity，`ArvrRuntimeService` 常驻，但日志里没有任何 SLAM / 6DoF 初始化输出 —— 它在等 `vr_system` 的连接回调，闸门没开就什么都不做。

## 缺口归因

三类问题，优先级从低到高：

**① Android 11 收紧 Settings.System（低成本，已绕过）**
`PRIVACY_ACCEPTED` 这类自定义键不能再写。用 `settings put system` 预置即可，不用改包。

**② 缺华为框架类 `com.huawei.android.os.SystemPropertiesEx`（中成本）**
影响虚拟屏、视频两个包。工程里 `shared/java` 已经有这批桩类的计划（40 个），但当前机器**没有可用 JDK**（`jdk17tmp/jdk/bin` 只有 `server`，无 `javac`），编译不出 dex。三条路：
- 装一个真 JDK（最直接，顺带解锁 apktool / apksigner）
- 从固件的 `boot.art`/vdex 里把类抠出来（工作量大）
- 直接用 LSPosed 做类替换（需先装 Zygisk + LSPosed）

**③ 缺 frameworkhwext 资源包（中成本）**
`commonui_custom_titlebar` 引用的 `0x02xxxxxx` 属性。要么塞一份 `frameworkhwext-res`，要么把布局里那个 attr 改成字面量重打包。后者用现成的 `tools/apk-repack-sign.py` + `patches/axml_edit.py` 就能做。

**④ `vr_system` 不存在（高成本，但绕得开）**
要么让 `vrservice` 重新以 system uid 运行（系统层做，等于改 ROM），要么不走华为那套：直接调 `hvrsdkserverapp` 的算法库 / 用 ALVR 那条自研路线。这也是当前项目主线在做的事。

## 一句话

**2D 部分（商城、桌面 2D 壳）已经通了；VR 部分不是应用装没装的问题，而是缺三个东西：华为框架类、frameworkhwext 资源、`vr_system` 系统服务。** 前两个能补，第三个建议绕。
