# 2026-11-02 全栈分析汇总（华为 VR → RK3566）

> 本文是本轮（11-01 ~ 11-02）所有分析的汇总。逐项细节见文末索引，不重复展开。
>
> 一句话总账：**2D 链路全通（7 包零崩溃、商城可用、黑屏已修）；VR 链路卡在
> `vr_system` 一个点上 —— 它需要 system_server 权限，建议绕开华为栈走 ALVR。**

---

## 一、线缆固件 OTA：结论是"协议裸奔，但货架空了"

**问题**：能否伪造旧版本，骗服务端下发最新线缆固件？

**结论**：三环节里两环通、一环断。

| 环节 | 结论 |
|---|---|
| ① 请求可伪造 | ✅ 端点 `POST query.dbankcloud.cn/vr/v2/CheckEx.action` 无签名/无 token/无证书锁定，IMEI 都可留空 |
| ② 服务端有货 | ❌ `Firmware=0` 到 `99` 全部返回 `{"status":"1"}`（已是最新）—— 产品线 2021 年停产，端点活着但只回空壳 |
| ③ 拿到能刷 | ✅ VLI 私有命令刷写链路（controlTransfer 0xE0 → SPI 擦写校验）代码完整，但 APK 内无任何 .bin |

**意外收获**：`dumpsys usb` 显示线缆 hub 只上报 `2109:0105 Billboard`（class=17，
Alt Mode 协商失败的错误通知设备），`num_connects=139` 反复重枚举 ——
6DoF 起不来的真正嫌疑是**下游设备没被枚举/DP Alt Mode 抢带宽**，不是固件旧
（固件 c.9.52.6，第 3 段 52 > 47，能力位正常）。「升级鸿蒙 2 就好了」更可能是
显示栈的 DP 通道分配差异。

**工具**：`tools/cable-ota-check.py --sweep` 随时复验。

## 二、RK3566 部署：七包全栈落地

**设备**：H96_Max_RK3566，Android 11，`zygote64_32`（32 位可跑 —— 7 包里 6 个是
armeabi-v7a，纯 64 位系统装不了），Magisk 26.3。

三处硬卡点及解法：

1. **`sharedUserId="android.uid.system"`**（4 包）→ 平台签名永远对不上 Rockchip 系统UID，
   必须删属性降为普通应用，失去的权限用 appops/pm grant 显式补；
2. **本机无 JDK** → 初期用纯 Python + openssl 手搓 v1 签名（`tools/apk-repack-sign.py`：
   改二进制 manifest → 重算 MANIFEST.MF/CERT.SF → PKCS#7 → .so 页对齐），后装
   Temurin 17 转正；
3. **targetSdk≥30 强制 v2 签名** → `vrhandle`（31）降到 29 后可 v1 安装。

授权补齐走 `tools/grant-vr-perms.sh`；遗留：`SYSTEM_ALERT_WINDOW` 对未声明该权限的
4 个包 appops 不生效，需补 manifest 声明再重签。

## 三、HDMI 黑屏：EDID 被模块锁死

**症状**：接便携屏无信号，盒子一切正常。

**定位关键**：别信 `dumpsys display`（报 1080p，那是应用层），要看内核
`/sys/kernel/debug/dri/0/summary` —— 实际输出 3200x1600p70（clk 412MHz），1080p
便携屏锁不住这个像素时钟。

**根因**：hvrglass 模块开机无条件给 HDMI-A-1 注入 VR Glass 专用假 EDID
（眼镜读不出 EDID，必须注入才能亮）；但模块不分对象，普通屏也被骗死。

**修复**：`post-fs-data.sh` 改为按需注入（读到真实 EDID 就不注入），加
`edid-mode.sh show|vr|1080p` 运行时切换；现场修复 = 写 1080p EDID +
`setprop ctl.restart surfaceflinger`。经验：`edid_override` 写入即常驻、写 0 清不掉。

## 四、JDK 解锁与七包重建：三个必崩应用全部救活

装好 Temurin 17（必须落在 `AndroidSDK\jdk17tmp\<dir>\bin\javac.exe`，路径写死）后，
`build-module.ps1` 链路首次跑通。链上修了四处：

1. **javac stderr 触发 PowerShell 5.1 致命错** → `Invoke-Javac` 包装降 ErrorActionPreference；
2. **python 指向商店占位** → PATH 前置真实解释器；
3. **清理构建目录卡 7 分钟**（Remove-Item -Recurse）→ `cmd /c rd /s /q`（2.6 秒）；
4. **EMUI `androidhwext` 资源包 0x02 在 AOSP 不存在** → 新写
   `tools/patch-hwext-text.py`：删 `?androidhwext:` 属性取值、主题映射到 Holo 同源
   （详见下）。

逐包处置与结果：

| 包 | 处置 | 结果 |
|---|---|---|
| appmarket.vr | 重建（换签名需先卸载） | ✅ 2D 商城完全可用 |
| vrlauncherx | 重建 + `PRIVACY_ACCEPTED` 预置 | ✅ 到门禁页（隐私页不再崩） |
| vrvirtualscreen | 重解码 + 去 sharedUserId + hwext 补丁 | ✅ 到门禁页（原来启动即崩） |
| himovie.vr | 重建 + `SecurityDetect.irpj()` 恒 return 0 | ✅ 到协议页（原来是 root 检测自杀，无崩溃堆栈、极易漏诊） |
| vrhandle | 重建（hwext 属性修复） | ✅ 管理界面可用（原来 InflateException 0x020100c8） |
| vrservice | 重建 + 兼容层 classes4.dex | ⚠️ 进程在，`vr_system` 未注册 |
| hvrsdkserverapp | 重建 | ⚠️ ArvrRuntimeService 常驻空转 |

虚拟屏/视频崩溃根因 `NoClassDefFoundError: SystemPropertiesEx` 通过 JDK 编译兼容层
（桩类）打进包内解决。

## 五、缺口总账（按优先级）

1. **`vr_system` 未注册**（高成本，建议绕）：`vrservice` 改普通应用后注册不进
   system_server。它是桌面进 VR 空间、虚拟屏、SDK 握手的总闸。出路：LSPosed 在
   system_server 注册桩，或直接走 ALVR（设备已有 `com.lht.huaweivr.alvr`）。
2. **appops `SYSTEM_ALERT_WINDOW` 部分失效**（低成本）：4 包 manifest 缺声明，
   补声明 + 重签即可（`patches/patch_platform_permissions.py` 有逐包权限表）。
3. **平台类 40 个**（中成本）：`BuildEx`、`HwWidgetSafeInsets` 等 EMUI 类缺失告警
   都被 catch 住了不致命，但补齐需 LSPosed 或 bundled dex。
4. **USB 下游枚举**（先查物理层）：6DoF 嫌疑已从固件转向线缆/接口/带宽，接齐三件
   量一次拓扑（见 OTA 文档第六节）。

## 七、眼镜插入实机排查（21:25-22:00 追加）

### 7.1 插入眼镜为什么没有进入 VR 桌面

- **USB 链路是通的**：`2109:2211` hub → `12d1:1092 HUAWEI GLASS CV10`（IMU/HID）
  + `12d1:107E GLASS HID`，hidraw 权限守护正常。
- **卡点在软件感知链**：launcherx 清单里**没有 USB 插入 receiver**——华为设计里
  进 VR 靠 `vr_system` 服务报设备状态，不是 USB 事件。logcat 实锤：
  `HvrServiceManagerEx: no application context; vr_system stays process-local`
  （兼容层桩只在 vrservice 进程内）→ 门禁永远拦。结论同缺口 #1。

### 7.2 眼镜里画面"超出范围"的根因（关键）

- 眼镜真实 EDID 这次能读出（厂商 HWV）：3200x1600@**90**（首选）+ @70，
  两模式总光栅完全相同（3308x1780）→ **@70/@90 几何一致，切时序救不了尺寸**。
- composer HAL（`vendor.hwcomposer-2-1`）把 HDMI 当固定 1080p 内置屏，
  supportedModes 写死 1080p60；EDID override + 重启 SF + 重启 composer 都不改
  VOP 输出（CRTC 咬死 p90），只有**整机重启**（模块开机早期注入）才可靠。
- **真正根因**：VOP 把 1920x1080 桌面**拉伸铺满 3200x1600 双目面板**
  （src 1920x1080 → dst 3200x1600），每眼只看到桌面一半 → 图超大超边。
  这不是 bug，是"2D 桌面喂立体面板"的天然结果。
- **出路**：① himovie.vr 的 SBS 播放（立即可用）；② ALVR 串流；
  ③ vrvirtualscreen 虚拟桌面（被 vr_system 挡）；④ 自写 SBS 镜像 app。

### 7.3 对 fix 包的使用修正

- 模块 mode 默认 `auto`：**接屏能读到真实 EDID 就不注入**。眼镜 EDID 可读时
  auto 会失效（本次实测），接眼镜前建议：
  `su -c 'echo force-vr > /data/adb/hvrglass/mode'` 然后**重启整机**；
  换回便携屏时改回 `auto`（否则便携屏会被喂 3200x1600@70 黑屏）。
- 运行时切换用 `sh /data/adb/hvrglass/edid-mode.sh vr|1080p|show`（免重启）。
